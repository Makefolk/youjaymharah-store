# Daily operations

**Audience:** support, fulfillment and the shift lead.

**Prerequisites:** an
individual staff account, assigned responsibilities and working access to the
approved gateway/courier systems where needed.

## Start the shift

1. Check the storefront and incident channel for an active outage.
2. Open **Attention**. Review open support, email review, payment discrepancies,
   waiting returns and paid orders that have not shipped.
3. Assign each actionable item to a named person. Prioritize customers with
   money taken, blocked deliveries, private-data concerns and overdue promises.
4. Compare gateway settlements with orders using the established reconciliation
   procedure. The attention panel alone is not a complete financial ledger.
5. Review today's stock, dispatch cutoff and courier arrangements.

## Work an order

Confirm the order's payment is captured, check item quantities and the shipping
address, then follow [fulfillment](/staff/fulfillment). Use the order's email
history and support context to avoid sending conflicting updates or duplicating
work. Check existing return/refund records before making another change.

## Handle an exception

| Exception                                    | Owner action                                                          |
| -------------------------------------------- | --------------------------------------------------------------------- |
| Customer paid but no order exists            | [Payment recovery](/customers/payments#staff-recovery)                |
| Email acceptance is unknown                  | [Email review](/staff/email)                                          |
| Goods are being returned or need replacement | [Returns and refunds](/staff/refunds)                                 |
| Private data or account access is involved   | [Security procedure](/operations/security)                            |
| Several customers have the same failure      | Open an [incident](/operations/incidents) and coordinate one response |

## End the shift

Record each unresolved item's current state, next action, owner and expected
follow-up time in the proper internal system. Distinguish waiting for the
customer, courier, gateway and engineering. Do not mark a support request
resolved merely because a shift ended.

The next shift should be able to continue without repeating a payment, refund,
shipment or customer notification. Verify that no high-priority request or
paid-order exception is unassigned.
